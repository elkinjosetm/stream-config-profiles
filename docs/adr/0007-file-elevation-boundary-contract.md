# File-elevation boundary contract: bare-token switches, pre-resolved identity, single quoted command line

`manager.ps1`'s GUI re-launches itself elevated via `powershell.exe -File <manager.ps1> -Action <name> ...` for the operations that need admin rights (conf editing, service restart, protected-location uninstall, watchdog Logon registration). Two field failures during v0.1.1 hardening forced a structural fix: `-File` parses arguments as literal, unevaluated strings, so an explicit `-Name:$true`/`-Name:$false` token arrives as text and fails to bind to `[SwitchParameter]` at all (caught on both Windows CI legs); and a related PowerShell-5.1-only bug let a poll-only elevated retry silently re-register a declined Logon task, because `-IncludeLogon`'s "omitted means included" default required a `$PSBoundParameters`-based restoration that was lossy on the real 5.1 interpreter specifically. The fix: `ConvertTo-ElevatedArgumentString` renders every switch as a bare `-Name` for true and omits it entirely for false, never an explicit boolean token — the one shape `-File` binds identically on 5.1 and pwsh 7 — which requires every switch parameter that can cross this boundary to default `$false` (hence `-IncludeLogon` was replaced by `-SkipLogon` at the CLI); identity and paths that must not be re-derived under a different account (`-UserId`, `-DesktopDir`/`-ProgramsDir`) are resolved once pre-elevation and threaded through explicitly; and the command line is built as a single, fully-quoted string via `ConvertTo-QuotedCommandLineArgument`, not a `string[]` passed to `-ArgumentList`, guarding against injection from paths containing spaces or quotes.

## Consequences

The two-switch-name split (`-SkipLogon` at the CLI/elevation boundary vs. `-IncludeLogon` for in-process callers) is an extra concept a future maintainer must keep synchronized at the one conversion site (the bottom CLI dispatch) — getting it wrong silently reintroduces the original bug rather than failing loudly. Every new switch parameter added to any `-Action` must default `$false` if it can ever cross this boundary; this is a convention enforced by tests and comments, not the language.
