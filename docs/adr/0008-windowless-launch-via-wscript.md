# Windowless launch via wscript.exe + generated launch.vbs

Field feedback on v0.1.1: launching the manager from its Start Menu/Desktop shortcut showed a Windows Terminal console window alongside the GUI, because Windows Terminal (the default console host on Windows 11) doesn't reliably honor `-WindowStyle Hidden` requested of `powershell.exe` directly. The shortcut now targets `wscript.exe "PROGRAM\launch.vbs"` — a two-line generated Windows Script Host file (`Get-ManagerLaunchVbsContent`, written into PROGRAM by `Install-App` and removed with it on uninstall) that runs the manager via `WshShell.Run(..., 0, False)`; `wscript.exe` is a genuinely windowless host, so no console is ever created regardless of the user's default terminal. This is scoped to the end-user launch path only — the STA self-relaunch, the elevated `-Action` re-entry, and `Setup.bat`'s own extraction step all deliberately stay on plain `powershell.exe -WindowStyle Hidden`, since each is a child process of a session the user already started (or a batch window they're watching install progress in), where a brief console flash is acceptable and wscript's windowless semantics aren't needed.
